### 00:00–00:25 项目介绍（标题卡 → 终端）

> 大家好，我们是第三组"在阴雨天游泳"。我们的项目是 LoCoMo Dynamic Memory：在长期、多会话的对话里，系统把对话整理成带来源和时间的记忆，回答问题时给出可以回查原文的引用。
> 下面是真实网页的操作演示。演示使用离线合成回放：页面读取预先保存的合成数据和问答记录，不调用模型，也不需要密钥。

### 00:25–00:50 打开 Console

操作：浏览器打开 `127.0.0.1:18501` → Overview → 鼠标停在"合成回放 / 对话 / 当前版本"三个标签 → 展开"数据与版本"，指向 Build 指纹 → 收起。

> 这是合并进主分支的 Research Console。顶部标明当前是合成回放、所选对话和构建版本。每次查询都固定在一个完整版本上，记忆、关系和索引来自同一版本。

### 00:50–01:30 当前状态与历史状态（Memory）

操作：Memory → 点 "Alex lives in Paris." → 点 "Alex lives in Rome." → 向下滚到"这条记忆的关系与冲突"，停在"替代"→ 回到顶部，点 "Alex plans to visit Tokyo."，指向"计划"标注。

> Alex 先说自己住在巴黎，第二天说从巴黎搬到了罗马。系统没有删除巴黎这条，而是建立"替代"关系：当前状态是罗马，巴黎作为历史保留下来。
> 每条记忆还记录陈述性质。比如"打算去东京"被标成计划，不会被当成已经去过。

### 01:30–02:00 Memory 与 Source

操作：保持选中 "Alex lives in Rome." → 指向"原文证据 · 来源 1 · D2:1"与原文 "I moved from Paris to Rome on 2 May 2023." → 展开"核对来源身份"→ 回到 "Alex lives in Paris."，原文切换为 "I live in Paris."。

> 每条记忆都指向原始对话轮次。来源由数据集、对话和轮次编号共同确定，切换记忆，原文也随之切换。
> 引用编号合法，只说明它指向真实原文；原文是否真的支持回答，我们在实验里另做了审阅。

### 02:00–03:05 Query 与 Trace

操作：
1. Query → 选"当前事实"→"载入冻结案例"→ 指向 "Alex lives in Rome." 与来源 D2:1（约 12 s）。
2. 选"历史日期"→ 载入 → 指向 "Alex lives in Paris." 与来源 D1:1（约 12 s）。
3. 视图设置 → 评审者 → 展开"评审详情 · 阶段 Trace"→ 依次点 initial / expanded / effective/delivered / answer/citations，每个停 4–5 s。
4. 视图设置 → 展示者。

> 同一个问题"Alex 住在哪"：问现在，回答罗马；问历史日期，回答巴黎。两次都给出对应的原文。
> 展开 Trace，可以看到证据经过的四个阶段：初始检索、历史扩展、有效证据，以及最终交付给回答的引用。我们的错误分析，就是逐阶段比较这些集合在哪里变少。

### 03:05–03:15 其他案例（快速）

操作：点 Demo 页 → 鼠标从上到下扫过六个案例卡片（不点开）。

> Demo 页还准备了证据冲突、证据不足和预算失败等案例：冲突会保留双方来源，证据不足不会编造，失败会完整记录而不当成"没有证据"。

### 03:15–03:55 实验结果

操作：Experiments → 指向"原 Run 计划组合 3028"→ 成本策略切 Hybrid / Dynamic（约 12 s）。切到报告图 F5 + F6（左上角标"报告图表 · E25 留出实验 · 冻结运行记录"），停约 20 s。

> 实验页展示的是早期在开发对话上的 757 题历史结果，成功子集和完整分母分开显示，费用是历史价格估算。
> 最终结论来自独立留出实验：两段开发期间没看过成绩的对话、400 道题，两种策略各真实调用模型运行一次，配置在读取标准答案前锁定。今天的演示没有发起调用，但那次运行的 2,112 次真实请求都有冻结记录。
> 事实类问题上，Hybrid 的 F1 是 0.403，Dynamic 是 0.409，差值的 95% 区间跨过零，所以本实验没有充分证据证明 Dynamic 稳定更好。而 Dynamic 按已报用量估算的费用约是 Hybrid 的 7.9 倍，中位延迟约 3.5 倍。

### 03:55–04:30 总结

操作：回到 Overview；最后 5 s 结尾卡。

> 所以我们默认使用 Hybrid，Dynamic 保留为可选项。
> 分析还发现，标注来源的减少主要发生在 Dynamic 的解析步骤；这些被排除的来源是否真的应该保留，还需要人工逐题核查。Graph、压缩、自适应和时间 Sidecar 目前是研究候选，没有证明对问答有收益。
