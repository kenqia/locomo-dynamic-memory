## What to build

使用者能重试中断构建并检查失败片段；重建期间仍查询旧完整版本，只有新 Memory、关系、投影和索引全部就绪才切换。该票强化已有构建与候选查询，不依赖答案生成是否完成。 使用者选择完整构建版本并下载统一 JSON，导出的 Memory、多来源、关系与状态信息和页面可见版本一致，可逐项追溯原文。

父 spec 用户故事：US8、US9、US28、US29、US30、US31、US32、US33、US49、US50、US51、US52、US59。本票贯穿数据、公开 API、页面及行为测试；只替换 LLM/Embedding，未实现功能不得伪装已完成。

## Acceptance criteria

- [ ] 沿用现有 BuildVersion 和片段进度，重启明确识别中断，支持显式恢复/重试，不重复写入成功片段。
- [ ] 全局只运行一个构建任务，进度与失败经 API 和页面可见，不引入外部任务队列。
- [ ] 同一完整版本绑定 Memory、关系、Current State 与索引；未完成的检查结果不能被当成完整查询源。
- [ ] 新版本全部检查通过后原子发布，失败保持旧完整版本可用；首次无完整版本只允许检查进度和部分产物。
- [ ] 候选查询在请求开始固定版本，切换期间仍使用同一版本全部产物；后续问答复用该选择契约。
- [ ] 数据、Prompt/schema、模型或产物相关配置变化有新指纹，重复导入/重试行为明确，凭据不进入快照。
- [ ] API 故障注入验证部分成功、重启、重试幂等、发布失败、并发查询与版本切换，不依靠具体 SQL 或内部调用顺序断言。
- [ ] 后端导出有 schema 与版本身份，包含结构化 Memory、多来源以及说明该集合的关系与状态信息；页面提供实际下载入口。
- [ ] 单 Memory 多来源、多 Memory 同来源保持完整，跨会话来源可定位；不混入其它版本的关系或索引身份。
- [ ] 只以明确所选完整版本输出，不把部分构建伪装完整导出；导出期间版本切换也不能混合内容。
- [ ] 不导出凭据或 QA 参考答案，字段与 ID 可验证，内容与页面选择和持久化记录一致。
- [ ] 通过 API 验证 JSON 解析、schema、版本一致性、来源存在性、失败和秘密排除；浏览器冒烟验证下载入口。
