## What to build

新 Memory 与相关历史比较后，使用者能在页面查看有证据支持的关系及 Current State，并回看旧阶段与旧事实。保留冲突和关系未确定，不能用最新记录无条件覆盖历史。 在初始候选之后，页面展示沿已有关系及同一状态维度补入的历史、扩展入口与截断，能找回阶段推理所需但初始未命中的前序 Memory。

父 spec 用户故事：US14、US15、US20、US21、US22、US23、US24、US25、US26、US36、US37、US38、US39、US54、US58、US59。本票贯穿数据、公开 API、页面及行为测试；只替换 LLM/Embedding，未实现功能不得伪装已完成。

## Acceptance criteria

- [ ] 维护与构建版本关联的关系，含两端 Memory、标签、来源、理由和适用条件；校验关系引用属于正确对话与版本。
- [ ] 按父 spec 的 RETAIN、UPDATE、SUPERSEDE、CONFLICT 定义判断；证据不足保持未确定，不把无新消息判为 RETAIN。
- [ ] Current State 从历史与关系重算，不作为可独立修改的真相；修正错误通过显式重建，不增加在线状态编辑器。
- [ ] 页面可从关系和状态跳转双方原始证据；旧事件和前序阶段仍保留，同键兼容事实可以共存。
- [ ] 研究→申请→面试支持 UPDATE；明确搬家可支持替代；失业和开店不能仅因同一人物而互相替代。
- [ ] API 测试以受控关系判断配合真实 SQLite 验证规则、来源、冲突共存、同名隔离、投影重算和不删除历史。
- [ ] 后续票可读取统一关系与状态契约，不需要为展示重新建立一份 Memory。
- [ ] 从初始候选扩展一跳已有关系，并补充同一 state_key 下与问题时间有关的历史；同键补充不再触发第二轮遍历。
- [ ] 默认初始与补充去重合计不超过 60 条，数量、深度、排序及 token 预算集中配置并记录。
- [ ] 每条补充记录保留入口和理由，初始集合与扩展集合分别可查；触顶明确显示截断，不宣称完整证据。
- [ ] 不跨对话混入同名实体，不因同人不同状态维度就无条件连通；既有有效关系仍可按其条件使用。
- [ ] 构造真实初始检索漏掉研究阶段的样例，扩展可找回；未抽取该事实的反例不能被假装恢复。
- [ ] 通过 API 和真实关系库/检索验证一跳、同键补充、稳定去重、预算变化、截断与来源，不 mock 历史扩展本身。
