## What to build

使用者对人工检查的合成案例运行评测，在页面查看 QA 结果、各检索阶段的来源覆盖、不可计分原因与样本覆盖率，后续可接入课程正式数据。 使用者在同一评测流程选择 Full Text、无状态判断的 Vector RAG 或关闭状态解析的系统消融，查看结果和配置差异，能判断改进来自哪个环节。

父 spec 用户故事：US4、US5、US50、US53、US54、US55、US56、US57、US58、US59、US60、US61。本票贯穿数据、公开 API、页面及行为测试；只替换 LLM/Embedding，未实现功能不得伪装已完成。

## Acceptance criteria

- [ ] 独立评测输入与原始 conversation 构建隔离，不把 QA 答案/evidence 或辅助摘要传给抽取、索引和线上解析。
- [ ] QA F1 对齐官方规范化、词干化与类别分支；缺答案和对抗类别按可用标注处理并可检查，不能未经说明替换普通 token F1。
- [ ] 区分 Memory 排名与去重 Source Turn 证据，分别记录初始、扩展和有效集合；明确 K 单位、阶段与诊断口径。
- [ ] 保留 evidence 原文；复合合法 ID 拆分逐个校验，畸形或不存在的引用不猜测修正，修正映射单独可审查。
- [ ] 无法可靠映射的证据分标为不可计算，仍计算适用 QA 指标；显示计分、未计分样本数及覆盖率。
- [ ] 具备课程划分/动态标注的接入与校验点，缺失时明确报告未评，不擅自选 4/2、不伪造动态准确率或用 LLM 自标作真值。
- [ ] API 测试覆盖复合、缺失和畸形引用、分母覆盖率、类别处理、评测泄漏隔离及可观察错误；真实数据仅做结构/映射检查，正式划分前不反复调策略。
- [ ] 页面展示结果与失败案例，并按实际独立证据区分抽取、召回、扩展、解析错误；不足时仅报告可能原因。
- [ ] 三种对照在现有 API/评测流程与页面可选择，策略语义明确：Vector RAG 不进行状态解析，系统消融仅关闭被研究的状态判断。
- [ ] 固定或明确记录生成模型、Prompt、生成参数、对话范围、最终证据/token 预算、上下文截断和额外调用；不能把不同上下文长度隐去。
- [ ] 保存实际配置、版本、耗时、模型调用和 token 用量，页面能并列查看结果与失败；不预设性能提升比例。
- [ ] 依赖缺失时明确跳过正式课程指标，不把合成样例诊断当作测试集结果，不用测试集调参。
- [ ] 用受控 LLM/Embedding 和真实检索验证策略差异确实生效、预算与配置有记录、指标汇总一致；真实模型评测单独标记且有限样例。
- [ ] 不新增外部搜索、图检索或自动优化器，不为对照复制第二份全局状态。
