# Milestone 2：Vision & Scope

项目：动态对话记忆管理。拟用仓库名：`locomo-dynamic-memory`。

状态：草稿，2026-10-04，经组长允许存入私有仓库，尚未形成正式需求基线。目标是排版为不超过 5 页的 PDF，实际页数尚未验证。本文依据课程课件及用户提供的教师答复整理，不代表已经实现或已经取得实验效果。

## 1. 问题与愿景

长期对话记录包含人物经历、计划、偏好和状态变化。检索到相关信息后，系统仍需判断这些信息是否适用于当前问题。旧状态与新状态混用，会让答案看似有证据，却回答了错误的时间条件。

我们计划构建一个可追溯的动态记忆管理 Web 应用。用户导入长期对话并提问，系统检索历史记忆，判断保留、更新或替代关系，再依据问题与时间条件选择有效记忆。用户能查看答案依赖的原始轮次和选择过程。

示意场景：某人先说住在城市 A，后来明确说搬到城市 B。问“现在住哪里”与“搬家前住哪里”需要不同证据。系统不能把最新信息一律用于所有问题，也不能删除旧记录后失去历史问题的依据。此场景为说明用途而构造，不是已验证的 LoCoMo 样本。

## 2. 使用者与使用流程

主要使用者是项目组的开发与评测人员，以及运行系统并检查结果的教师或助教。起步范围不包含面向公众的账户系统或多人服务。

基本流程：导入对话 → 构建并保存记忆 → 查看记忆和原始证据 → 输入问题 → 检索候选 → 判断状态关系与有效性 → 生成答案并展示证据 → 导出结构化 JSON。

一次构建的记忆应可重复用于多个问题，避免每次提问都从头抽取。保存和加载方式尚未选型。

## 3. 范围与主要功能

| 编号 | 功能 | 可检查的完成依据 |
| --- | --- | --- |
| F01 | 导入课程 LoCoMo 对话 | 保留人物、会话、轮次及时间来源；非文本附加字段的处理有说明，不破坏证据编号 |
| F02 | 构建结构化记忆 | 每条记忆含内容、时间和来源；可从记忆定位原始证据 |
| F03 | 保存、复用与 JSON 导出 | 记忆可再次读取；导出记录与 Web 展示对应，字段含义有文档 |
| F04 | 检索相关历史记忆 | 返回可追溯的候选；检索结果可映射为评测证据轮次 |
| F05 | 判断状态关系和有效性 | 支持保留、更新或替代；按问题与时间条件选取有效记忆；矛盾或证据不足时展示不确定性 |
| F06 | 生成可检查的回答 | 使用获准模型生成答案；展示相关历史、采用的证据和状态判断，不伪造来源 |
| F07 | Web 记忆与证据展示 | 用户可浏览记忆、查看原文、提问、查看结果并导出 |
| F08 | 测试与对照分析 | 记录 F1、Recall@K、状态判断结果及对照方法；保留配置和失败案例 |

基本冲突标识不等于复杂冲突消解。图记忆、多跳、自动合并压缩、复杂时间推理和自适应检索先列为候选扩展，不作为首版承诺。暂不做外部知识搜索、图片理解、生产级多租户或完整复现参考论文。

## 4. 候选实现路线与小规模探索

先建立最短可检查链路：结构化记忆 → 候选检索 → 查询相关状态判断 → 有效证据 → 回答与展示。四个模块遵循共同样例和输入输出约定，允许在契约不变时替换内部实现。

组长负责整体设计、状态判断和集成；B 负责记忆构建；C 负责检索与对照；D 负责 Web 与端到端验收。具体成员和技术栈尚未确认，完整接口字段将在核对实际数据和评测入口后制定。

首个研究重点是查询时间条件下的有效记忆选择。这是课程核心任务，不能仅凭实现它就宣称算法创新。候选扩展是清楚展示不采用某条记忆的原因，并评估这是否帮助定位错误；是否纳入扩展由工作量和实验结果决定。

保持原始来源可追溯，不把一次查询的状态判断永久覆盖到全局记忆上。历史问题与当前问题可以选择不同有效证据。若状态判断未改善回答，应分析检索遗漏、时间理解错误或错误替代，而不是隐去负面结果。

## 5. 数据与验证计划

按课程指定的 6 段对话组织数据，4 段用于开发与调试，2 段用于独立测试。具体划分待课程通知确认。开发 QA 标准答案和证据只用于评测，不作为供系统检索的对话记忆；独立测试集不用于调参。

| 检查项 | 方法 | 注意事项 |
| --- | --- | --- |
| 回答质量 | 按课程脚本计算回答 F1 | 记录脚本版本和答案规范化口径，不自行替换指标 |
| 证据召回 | 按课程脚本计算 Recall@K | 核对 Memory 到原始轮次的映射；K 值待确认 |
| 动态状态判断 | 与课程状态关系及有效记忆标注比较 | 核对标签定义、评价单位和计算口径 |
| 系统完整性 | 验证导入、复用、提问、证据展示和导出 | 同时检查空结果、异常输入和 API 失败 |
| 对照与诊断 | 比较 Full Text、Vector RAG 和项目方法 | 尽量固定模型与生成配置，记录证据预算和额外模型调用 |

Full Text 使用完整对话作输入；Vector RAG 检索相关记忆，但不做状态关系判断。对照配置需说明截断与上下文限制，不把被截断输入称为真正的全文。另可在项目方法中关闭状态判断，检查其单独影响，此项为建议的消融实验。

当前不设未经证实的准确率目标。验收重点是可运行、可复现、证据可追溯，并如实报告效果与不足。模型、接口、思考模式关闭方式、预算和调用记录字段需确认后才能开展付费实验。

- 指定数据、评测脚本和助教输入输出约定未取得，接口保持候选状态。
- 记忆抽取可能遗漏事实或时间；保留来源、失败样例和复核入口，不靠新增复杂组件掩盖问题。
- 首版不引入难逆转架构。扩展效果不明显时可移除扩展，保留必做链路、实验记录和负面结论。
