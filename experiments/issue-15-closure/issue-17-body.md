## What to build

使用者从评测计划启动运行，首次生成前即取得持久 Run ID，在页面或公开 API 查看逐项进度、结果和尝试历史。重启后可以显式恢复原运行，继续尚未完成项，跳过已提交成功项，并明确选择是否重试失败或结果未确认项。

父规格用户故事：US17、US26、US27、US28、US29、US30、US31、US32、US33、US34、US35、US50。

## Acceptance criteria

- [ ] 首次模型调用前校验并固定所有涉及对话的完整 BuildVersion，保存计划、原始输入与划分、策略、配置、Prompt/schema、计分版本和实现身份；未完整构建的对话不能执行。
- [ ] 公开创建入口及时返回持久 Run ID，无需等待全量结束；页面和 API 可读取计划总数、各项状态与已提交结果，缺少完成时间或最终汇总时不会崩溃，也不把部分结果显示为已完成。
- [ ] 每个样本与策略组合结束后立即事务保存成功结果或安全错误、Trace、尝试记录、耗时及 provider 已报告用量，后续失败不丢失此前已提交工作。
- [ ] 提供页面和公开 API 的显式恢复行为，核对数据、问题及顺序、划分、策略、固定构建、配置、Prompt/schema、计分版本和实现身份；实质不兼容时拒绝混合，保留旧结果。
- [ ] 恢复跳过已持久化成功项；读取记录、再次读取或恢复已完成 Run 不调用模型；已记录失败或结果未确认项只能按使用者的显式选择重试。
- [ ] 区分待执行、执行中、成功、失败、中断及外部结果未确认；模型返回后、事务提交前退出的窗口不伪装成功，不承诺 provider 恰好一次计费，页面说明其可能已经计费。
- [ ] 重试成功保留原错误、各次尝试和可追溯用量，逻辑计划项不因重试重复计数；汇总当前采用结果与历史首次失败可以分别核查。
- [ ] 复用本地单进程和后端所有权约束，同一 Run 的重复启动、并发恢复或冲突执行被明确拒绝；不引入外部队列、分布式锁或自动恢复循环。
- [ ] 重启后保留已提交项，将原活动运行明确标为中断或结果未确认，不假称原任务仍持续；新活动版本发布不改变本 Run 固定的完整版本。
- [ ] 公开 API 测试使用真实 SQLite 和受控外部模型，验证即时 Run ID、执行中可见性、逐项保存、后续失败、重启读取与恢复，并以 provider 调用记录证明已提交成功项未重跑。
- [ ] 覆盖身份改变拒绝、重复恢复完成运行、显式失败重试、并发冲突、未知窗口与尝试历史；不使用私有 SQL 或内部循环顺序作为断言，不用受控语义结果冒充真实模型质量。
- [ ] 旧评测记录和现有完整构建保持可读；必要的单项执行整理先保持既有四策略语义，更新页面调用与进度、恢复说明，不修改认证或全局配置。
