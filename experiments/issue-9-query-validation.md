## TDD 与场景

首条当前/历史 tracer 在 `POST /queries` 返回 404 时失败，实现后通过。随后将真实 `initial_k` 设为 1，确认初始确实遗漏一条住所 Memory，现有扩展补入该旧证据，历史问答可采用 Paris，当前采用 Rome。当前、历史、当前交叉提问后，从公开 API 读取的全局关系与 Current State 保持相同。

其他公开 API 场景检查如下：

- 错误版本的解析 ID、来源不属于有效 Memory 的回答引用，在实际 DeepSeek 适配器按有限配置重试后失败。错误含可读取的 Trace ID，失败阶段、调用次数与安全错误码可见，不伪装成证据不足。
- 解析中的空白理由/说明最初落入回答阶段失败。补充失败阶段断言后先红，再增加解析非空白校验转绿，防止用后续失败掩盖解析缺陷。
- 原问题的英文日期 `1 May 2023` 最初仍锚定当前，测试失败。增加单个明确英文年月日与 ISO 日期解析后转绿；多日期范围不擅自取首个端点，保留给有效证据解析。
- 同条件冲突保留两条事实及双方引用；计划不当作已完成搬家；未知关系只作为本次 Trace 补判保存；缺少相关信息返回不足。
- 请求证据之外的未来日期强制保留不足。真实最终证据预算为 1 时不传入放不下的 Memory，Trace 记录遗漏与截断；回答不会收到未送达证据。
- 用可控模型 HTTP 边界事件暂停查询分析，在另一公开 API 调用中完成并发布新版本。释放查询后初始、扩展、最终证据与引用仍全部属于请求开始时固定的旧完整版本。
- 首次构建未完整发布时返回 `no_complete_version`；中文问题返回安全输入错误。
