## 4. 版本控制约定，待全组确认

建议主分支为 `main`，每项任务使用短期分支。文档和代码经至少一位非作者成员复核后合入，组长负责协调集成。是否采用仓库强制保护由团队确认，不在本草稿中声称已经配置。

提交信息采用 `类型: 具体改动`，例如 `docs: 补充有效记忆验收场景`。建议类型为 `docs`、`feat`、`fix`、`test`、`chore`。提交描述真实改动，任务编号写入变更说明；成员使用自己的账号提交，不代造贡献历史。

建议阶段交付用 `milestone-1-v1` 等标识。文档草稿从首次提交开始留痕，修订保留历史，不覆盖掉旧版本的证据。AI 生成内容由责任人审查，代码需检查接口、来源映射、异常行为和测试结果。

不提交真实 API key、token、cookie 或 `.env`。后续只提供不含真实凭据的 `.env.example`，具体配置方式在技术选型后补充。
