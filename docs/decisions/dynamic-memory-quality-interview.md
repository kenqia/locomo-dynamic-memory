用户再次回复“全部接受推荐”，确认 Q4–Q6。以下为已确认方向，具体代码尚未实施。

4. **UPDATE 的结构化阶段依据。** 仅对新生成的 UPDATE 增加 `update_evidence`：旧、新两端分别提供阶段摘要、对应来源 ID 与连续逐字引句，并显式给出严格布尔值 `same_process` 和 `real_stage_changed`。沿用 `reason` 解释同一具体过程的连接依据，避免重复增加自由文本。UPDATE 要求两项布尔值均为 true，双方引用属于各自端点；不一致时走既有校验失败与有限重试，不读取自由文本理由强改标签。构建判断与查询补判使用同一契约，提升版本及指纹。旧记录保持可读，不补造阶段依据，也不宣称通过新校验。此方案不新增依赖或专用复核模型阶段，但会增加部分输出量。它不能拦住模型同时误判阶段、布尔值及标签，因此仍须独立语义验证，不视为 172 已解决。
5. **兜底的调用范围与剩余风险。** 在已有一次有效证据解析中报告各回答项的证据与缺口，不增加独立问题规划模型。无缺口时维持原调用次数；触发后最多一次有界原文检索及一次联合证据解析，然后回答，仍不足就停止。这里的一次指逻辑操作，既有有限重试可能产生多次实际 HTTP 请求，全部接入原账本。接受模型仍可能漏拆子问或误报充分的风险，使用独立对照验证，不承诺恢复所有遗漏。片段数量、扫描量、实际序列化文本预算及来源固定方式在实施方案中给出可审核默认值。
6. **部分可回答时的产品语义。** 整体仍为 insufficient，但逐项回答证据支持的已知部分并引用，明确指出其他部分的证据缺口。例如“她搬到了哪里，哪天入职？”可答“搬到了 Rome〔来源〕；入职日期证据不足”。不得补齐未知部分，不得把最后已知状态写成查询时已确认的现实；未来日期、未知条件或缺失冲突一方也不能因剩余证据而变成确定结论。当前 schema 已容许 insufficient 带非空证据与引用，本项需要澄清 Prompt、文档及复合问题回归。

## 已确认增量范围与验收条件

以下初始实施方案随最终确认获用户接受。数值是可逆的工程默认值，尚非当前生效配置或实验结论；选择算法、预算及实际参数均须进入相应指纹和 Trace。本轮不安装依赖，不修改认证、配置、hooks 或运行数据库。

### A：抽取示例

在实际 `ExtractionBatch` 契约下增加少量合成上下文及合法 JSON 输出，覆盖计划与已发生事实、说话人与第三人称指代、阶段、否定。错误做法用明确的文字解释，不提供容易模仿的错误 JSON。保留现有严格来源、时间和类型校验，提升抽取 Prompt 版本。不引入跨批实体注册表或新的抽取架构；跨批指代能力仍需如实报告。

验收包括示例按真实 schema 校验、通过公开构建 API 保存计划/事实/否定/阶段的成对案例、来源不可越界、指纹随 Prompt 改变。受控模型证明流程和契约，真实抽取语义另审，不用“Prompt 包含某句话”代替行为验证。

### B：关系候选

候选域为同一构建、同实体的全部先前 Memory，先后仍按来源顺序定义，不先截到最近 20。默认总上限维持 20，分为同键 16 席、跨键 4 席。同键先保护最多 8 条事实状态，再从其余同键记录补齐。否定状态、兼容的兼职及不同雇主均作为独立候选，不压成一个最新状态。

复用现有英文分词和 BM25 排序，主要使用内容与状态值，避免共同人物名主导匹配；随后按来源新近及稳定 ID 排序。同键或跨键池不足时空席借给另一池，有跨键候选时保留其配额。小于 20 的上限按固定比例缩放，1 席时优先同键。选择记录算法版本、分池、分数、借用、遗漏数及选中顺序；重试复用持久名单，不让模型元数据覆盖选择诊断。

选中只表示候选，不能称为已确认事件链或直接建立关系。事实保护不证明仍然适用；8 个事实席和 4 个跨键席均不保证全覆盖。同义改写及抽取实体/维度错误仍可能漏选。

验收包括远旧同键事实被超过 20 条近期计划/事件隔开仍可进入候选、多个兼容职位不合并、73 类跨键过程在大量同键干扰中仍有覆盖、去重、借用、小上限、稳定顺序、重试身份及截断诊断。真实 73 的候选覆盖必须独立离线检查，不从算法设计推断其已通过。此项独立记录对照，不宣称解决 172。

### C：172 与 UPDATE 阶段依据

按 Q4 为新生成关系实现条件性的阶段依据，构建和查询补判共同使用。非 UPDATE 不要求填写这份结构。新生成缺字段或显式否认同过程/阶段变化时拒绝，有限重试耗尽后保存失败，不降级为成功或静默改标签。错误只保存白名单诊断。

新契约、Prompt 和候选算法提升版本并创建新 Build 身份。旧关系按原关系版本读取并标明未通过新校验，旧中断 Build 不用新代码续跑。导出中的 Memory schema 版本不能冒充关系版本；新导出需要明确关系契约身份，旧导出保留可读性，不伪造阶段依据。

验收包括严格布尔值、双方来源归属、连续逐字引句、候选覆盖、版本恢复拒绝及旧导出读取。真实语义关卡继续核查 73 为 UPDATE、148/172 为有复证依据的 RETAIN 或保守 undetermined，并补充未写入示例的对照。结构通过、调用成功或理由变短均不能替代该关卡。

### D：有界原文兜底与部分回答

复用已有 `rank-bm25`，首版不新增原文 Dense 索引、供应商或依赖。使用原问题和明确证据缺口检索，推断人物或日期不作硬过滤。原文语料仅取 pinned Build 的 `build_fragments.source_ids_json` 所固定的完整输入清单，包含没有抽出 Memory 的轮次；在同一读取事务校验完整性及对话范围，按 position 加载。保存来源清单与内容摘要；来源完整性校验沿用导入规范化规则，不把数据库内两个相等的 hash 字段当成正文未被修改的充分证明。

初始上限为 3 个中心命中，每个中心最多补同 session 内前后各 1 轮，按 source_id 去重，合计最多 9 轮。先检查实际词面匹配，再按 BM25 分数和稳定位置排序，不以分数正负代替是否匹配。保存中心、邻轮、排名及省略原因。首版保留完整 SourceTurn，不新增文本 span 引用；超长中心轮跳过后继续尝试后续命中，邻轮省略须可见。上下文缺失可能影响指代或否定解释，不能因此强判充分。

原文的完整序列化内容及元信息最多 2,000 个 `regex-word-punctuation-v1` 近似单位，同时占用 Memory 与原文共同的 6,000 最终证据预算。来源联合、去重后传递，不能复用表示完整 Full Text 的无预算开关。首次和联合解析的完整 messages 初始上限均为 12,000 近似单位，覆盖 Prompt、schema、问题、时间、候选、关系和来源。输出 `max_tokens=8192` 单独记录；近似输入单位与 provider 输出 tokens 不混作同一 tokenizer 的上下文保证。

固定 Prompt/schema/问题本身超预算时返回明确预算错误。证据组放不下时记录省略与不足，不将其解释为原文没有信息；不得剪掉冲突一端后报冲突已消解。最终交付后按实际送达证据核对子问覆盖，丢失支持的子问降为不足，不启动第三轮解析。

无缺口不增加原文检索或模型操作；有缺口最多一次检索和一次联合解析。分别记录触发、命中、送达、有效、引用的来源与覆盖单位。混合引用需容许 Memory—原文及原文—原文的双边冲突，不能只按不同 memory_id 个数判断。查询不写回 Memory、关系或全局投影。

验收覆盖抽取遗漏可补回、原文同样不足、整体假充分但子问缺失、已知部分有引用、未来/未知条件仍未知、跨 session 与窗口重叠、超长/零命中、预算、双原文冲突、活动版本切换及新导入同名对话的隔离。Full Text 保持完整来源且超限显式失败，Vector 保持原始问题 Dense 选择，原 dynamic 保持 Memory-only 证据路径。

### E：有效证据解析精简

沿用 D 的完整请求计数与来源绑定，按问题相关性组织直接 Memory、必要前后状态及原文，减少无关项和重复元信息。不增加第二个通用规划器，不按最新时间或仅确定标签硬筛选。

以完整证据组保留关系端点、未消解冲突双方、兼容状态以及问题所需前序阶段，时间未知不直接排除。每次裁选记录保留/省略原因；组无法容纳时报告预算限制及证据不足，不用单边材料生成确定结论。保留可切换的 D 阶段方案作为消融对照，不让 P1 输入精简改变已记录的原文兜底效果。

验收包括历史问题、并存工作、未知替代时间/条件、最后已知状态、未消解冲突和否定。相对 D 的固定输入确实减少无关项或完整序列化体积，且关键证据未被误裁。若不能同时做到，保留 D，记录 P1 未通过，不为追求更少 tokens 放松语义。
