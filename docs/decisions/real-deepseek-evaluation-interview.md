## 强模型用途的方法依据

本轮使用 `agent-reach` 的 Jina Reader 读取公开一手资料，没有调用生成模型或将项目数据上传给标注服务。

- [OpenAI：Model Distillation in the API](https://openai.com/index/api-model-distillation/)介绍用强模型输出构造训练数据、微调学生模型并评估效果。只生成待核查标签属于数据生成或辅助标注，不能称为已经完成训练蒸馏。本次引用仅用于区分流程，不代表选择 OpenAI 服务。
- [MT-Bench / Chatbot Arena 原论文](https://arxiv.org/html/2306.05685v4)讨论模型评审的位置、冗长、推理与潜在自偏好问题。这支持对自动评审设置独立核查，不能直接证明 LoCoMo 动态标签可靠；论文也没有确定所有模型都会偏袒自身输出。

已确认的后续方向是让强模型依据原始对话、问题和明确标注规则生成带来源及时间条件的参考标签，由人独立核查用于准确率计分的小规模样本。未经核查的标签单列为模型生成参考，不冒称课程真值。

现有 `dynamic_truth` 绑定固定构建的 Memory ID。未来若从原始轮次标注，需要保留到固定构建 Memory 的可审查映射，并区分抽取遗漏与证据选择错误。当前接口不是可直接导入任意来源级动态标签的完整标注工具。

## 本阶段执行清单

本清单将已确认决定整理为可实施的顺序。片段大小、重试次数、检索 K 及模型设置沿用既有配置；下列预检数量和持久化粒度采用最小可逆方案。

1. 完成针对性准备改动。保存明确的开发/本地测试清单；让 Full Text 脱离 RAG 的截断预算并记录实际输入和超限；补齐运行成功率、补充得分，以及逐样本进度持久化与中断恢复。恢复必须校验数据、问题、策略、完整构建、配置和实现身份，避免混合结果或重复调用已成功项，不引入外部任务队列。
2. 运行变更相关的受控测试与真实本地 MiniLM 检查。检查凭据存在性，不读取或展示值；缺凭据时先完成可离线验证的准备，再报告实际缺项。首次真实请求前核对官方模型契约。
3. 执行真实小规模预检。先用已有 opt-in 检查验证 DeepSeek 抽取及来源，再构建完整 `conv-26`；按原始 QA 顺序为类别 1–5 各取首个问题，运行四种策略。预检检查结构、来源、完整版本、全文输入和可恢复记录，不设模型质量通过阈值，也不把五题成绩冒充完整结果。链路失败时保留错误和产物，定位后再推进。
4. 对四个指定开发对话构建并固定完整版本，在统一模型及生成参数下运行 `full_text`、`vector`、`hybrid_no_resolution`、`dynamic`。计划范围为 757 道 QA、3,028 个样本与策略组合；每项保存成功、失败或尚未执行状态，禁止静默遗漏。预检结果只有在全部身份一致且恢复机制可核实时才复用。
5. 汇总 QA 总体及分类结果、分对话结果、运行成功率与补充运行得分、初始候选/扩展/有效证据/实际回答上下文的独立来源覆盖，以及构建成本和查询成本、耗时、模型用量及失败。现有默认初始 K=20，单位为 Memory；完整全文来源覆盖单列，课程 Recall@K 口径仍待教师确认。
6. 留存数据/构建/实现/Prompt/schema/配置身份、逐项结果和可复现命令，整理有证据支持的失败案例。只有证据足够才将错误归为抽取、检索、扩展或有效证据解析；否则保留未定位。输出中将缺少独立真值的动态指标标为“未评”。

本阶段不读取 `conv-43`、`conv-44` 的模型成绩，也不开展基于成绩的优化或学生模型训练。新增模型辅助标注及冻结后本地测试属于后续阶段。当前没有远端写入授权，GitHub、Notion、PR 与课程提交均未执行。
